## 1. 守るべき硬い制約(3つ)

- [ ] **① 完全 in-repo(プロジェクト内で完結)**
  - [ ] `~/.claude` などプロジェクトディレクトリの外で管理しない。
  - [ ] リポジトリを渡す/コミットするだけで同じ挙動が再現できる(hermetic)。
- [ ] **② ベンダー中立**
  - [ ] Claude Code に密結合しない。
  - [ ] Codex / GitHub Copilot / Cursor など、すべてのベンダーで簡単に使える。
- [ ] **③ 人間が統治しない自己改善**
  - [ ] 目標に対してAIが試行 → その改善を設計哲学に反映して自己改善する。
  - [ ] 体系化された(管理されたしくみとしての)運用ができる。
  - [ ] 自律度 = **evalゲート自動承認**(改善した時だけ採用 / 悪化はrollback。統治するのは不変のGOALとeval)。

---

## 2. 設計思想の3層分離

- [ ] 設計思想を次の3層に分けて管理できる:
  - [ ] **普遍(プロジェクトに依存しない)設計思想**
  - [ ] **プロジェクト固有の設計思想**
  - [ ] **個人の設計思想**
- [ ] セッションに依らず、設計哲学のコンテキストを**効率よく取得**できる。
- [ ] 各層・各成果物の**責務を分離**して管理する(指示/手順/進捗/判断理由/強制設定 を混ぜない)。
